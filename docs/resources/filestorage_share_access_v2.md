# selectel_filestorage_share_access_v2

Creates and manages an access rule of a file storage for an IP address or a subnet in File Storage using the v2 public API. Any change replaces the rule. For an NFS file storage, the service applies the new list of rules within 15 minutes after a rule is added or deleted. For more information about access rules, see the [official Selectel documentation](https://docs.selectel.ru/en/file-storage/manage/configure-access-by-ips/).

## Example Usage

### Grant read-write access to one IP address

```terraform
resource "selectel_filestorage_share_access_v2" "share_access_1" {
  project_id   = selectel_vpc_project_v2.project_1.id
  region       = "ru-6"
  share_id     = selectel_filestorage_share_v2.share_1.id
  access_to    = "192.168.199.10"
  access_level = "rw"
}
```

### Grant read-only access to the whole subnet of an NFS file storage

```terraform
resource "selectel_filestorage_share_access_v2" "share_access_1" {
  project_id   = selectel_vpc_project_v2.project_1.id
  region       = "ru-6"
  share_id     = selectel_filestorage_share_v2.share_1.id
  access_to    = "192.168.199.0/24"
  access_level = "ro"
}
```

## Schema

### Required

- `access_level` (String) Access level: `rw` for read and write, `ro` for read only. Available values are `rw` and `ro`. A CIFS file storage supports only `rw`. Changing this creates a new access rule.
- `access_to` (String) IP address or subnet that gets access, for example, `192.168.199.10` or `192.168.199.0/24`. The format is an IPv4 address or an IPv4 CIDR without host bits, for example, `192.168.199.0/24`. `0.0.0.0/0` allows all addresses of the private subnet of the file storage and overrides narrower rules; no metadata key is needed for it. Addresses of other private subnets are allowed when they are routed to the subnet of the file storage, for example, through a global router. Changing this creates a new access rule.
- `project_id` (String) Unique identifier of the associated project, for example, `a07abc12310546f1b9291ab3013a7d75`. The value cannot be empty or start or end with whitespace. You can retrieve the project ID from the [selectel_vpc_project_v2](https://registry.terraform.io/providers/selectel/selectel/latest/docs/resources/vpc_project_v2) resource. Learn more about [Projects](https://docs.selectel.ru/en/control-panel-actions/projects/about-projects/). Changing this creates a new access rule.
- `region` (String) Pool of the file storage, for example, `ru-6`. The value cannot be empty or start or end with whitespace. It must match the pool of the file storage. Changing this creates a new access rule.
- `share_id` (String) Unique identifier of the file storage. The format is a lowercase UUID. You can retrieve the file storage ID from the [selectel_filestorage_share_v2](https://registry.terraform.io/providers/selectel/selectel/latest/docs/resources/filestorage_share_v2) resource. Changing this creates a new access rule.

### Optional

- `timeouts` (Block, Optional) Timeouts for access rule operations. (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) Unique identifier of the access rule. Import uses it together with the file storage ID. To get the access rule ID, use the [OpenStack CLI](https://docs.selectel.ru/en/cloud-servers/tools/openstack-cli/) command `openstack share access list <share_id>` and copy the `ID` field.
- `state` (String) State of the access rule, for example, `active`.

## Import

### In Terraform 1.5.0 and later

Use the [`import` block](https://developer.hashicorp.com/terraform/language/import) with the `id` attribute:

```terraform
# To get the rule UUID, run `openstack share access list <share_uuid>` and copy the `ID` field.
# Set the project and pool in the provider configuration or the
# INFRA_PROJECT_ID and INFRA_REGION environment variables.
import {
  to = selectel_filestorage_share_access_v2.share_access_1
  id = "<share_uuid>/<access_uuid>"
}
```

### All versions

Use the [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
# Import the existing access rule by the file storage UUID and the rule UUID.
# To get the rule UUID, run `openstack share access list <share_uuid>` and copy the `ID` field.
# Set the project and pool containing the file storage.
export OS_DOMAIN_NAME=<domain_name>
export OS_USERNAME=<username>
export OS_PASSWORD=<password>
export INFRA_PROJECT_ID=<project_id>
export INFRA_REGION=<region>

terraform import selectel_filestorage_share_access_v2.share_access_1 <share_uuid>/<access_uuid>
```

`<domain_name>`, `<username>`, and `<password>` are the arguments of the [provider configuration](https://registry.terraform.io/providers/selectel/selectel/latest/docs).

## Uncertain creation

If the API gives no definite answer to the create request, the resource looks for the access rule by the `selectel_tf_create_token` metadata key. When none appears, the apply fails, and the resource stays in state as `pending:<token>`. Refresh and destroy fail until the access rule appears. When it appears, the next refresh replaces the temporary ID with its UUID, and the next apply replaces the access rule; to keep it, run `terraform untaint` for the resource. If it does not appear, run `terraform state rm` for the resource, and the next apply creates it again.
